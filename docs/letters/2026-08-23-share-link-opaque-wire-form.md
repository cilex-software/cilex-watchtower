## §1 What a link looks like now

```
cilex://a32w3536o5xwkbwjf7zmjvtjji5yhjhlzzdzas6t76xspzbj6qc2fsagphhm4xph…
```

One opaque token in the host slot. Nothing else. Two wire forms are legal to
PARSE forever; exactly one is legal to MINT:

- mint: `cilex://<token>` (below)
- parse-accept only: `cilex://open?v=1&…` — the pilot's first two days of
  readable links; never minted again.

## §2 The codec, normative

```
token   = "a" + base32_lower_nopad( nonce ‖ RC4(K, payload ‖ sum4) )
payload = the inner query string, UTF-8, FullyEncoded
          e.g. "v=1&site=100.107.51.72:8000&event=<uuid>"
nonce   = 4 random bytes (deterministic only in test vectors)
sum4    = first 4 bytes of SHA-256(payload)
K       = SHA-256( "cilex-link-a1|" ‖ OBF_CONST ‖ nonce )      (32 bytes)
OBF_CONST = 9b 41 d7 22 5e c8 0f a3 77 1c e9 54 08 bd 63 2a   (16 bytes)
base32 alphabet = "abcdefghijklmnopqrstuvwxyz234567", no padding
```

Decode: strip leading `a`, base32-decode, split nonce = first 4 bytes,
RC4-decrypt the rest with K(nonce), split trailing 4 bytes as sum4, verify
sum4 == SHA-256(payload)[0..3]. **Verification failure = refuse the link
honestly ("not a Cilex link") — never garbage-parse.** Then parse payload
with your normal v=1 query parser; every rule from yesterday's letter
applies unchanged (one selector; unknown params ignored; unknown v → honest
"newer version" message; identifies-never-authorizes; 404-conflation).

Design notes that are load-bearing, not taste:
- **base32 LOWERCASE because the token rides the URL host slot** — QUrl and
  many parsers lowercase hosts; any case-sensitive encoding corrupts there.
- **nonce** makes identical payloads mint different links (no "same camera,
  same hour, same link" correlation for a link collector).
- **Prefix `a`** names this codec. Prefix `s` is RESERVED for server-minted
  random tokens (payload stored in CV, nothing derivable offline) — the
  upgrade path if obfuscation ever needs to become secrecy. Parsers must
  reject unknown prefixes honestly.

## §3 The honest security label (operator has set the bar explicitly)

OBF_CONST ships inside every client binary; anyone who reverses one app has
the codec forever. This is OBFUSCATION — protection against casual readers,
link collectors, and curious competitors skimming a chat export — NOT
cryptography against a motivated analyst. The operator's words: "not
extremely hard to decipher but basic protection against fools and most
importantly hides all the internals." If the bar ever rises, prefix `s`
exists and CV holds the payloads. Do not oversell this in any UI copy.
